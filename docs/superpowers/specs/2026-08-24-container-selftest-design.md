# repo-infra — the container self-test

Date: 2026-08-24
Extends: `2026-08-22-autotools-container-driver-design.md` (D18)

This document adds one decision, D19, and one CI block. It closes the gap D18
left open: the container driver was verified locally and never on a runner.

## The gap

D18 shipped an autotools container driver and proved it against a real container
on a developer machine. Every claim in that spec rests on local execution. The
one link nothing has exercised is **podman on an Ubuntu runner** — the line the
autotools CI block installs and the environment every converted repository will
actually build in.

Worse, the assets are the product. `container.mk` and
`m4/repo-infra-container.m4` are shipped, versioned files whose correctness is
asserted today by string assertions over their text. A test that greps a
makefile for `container-base` cannot tell whether `make` aborts. Three defects
this branch found — a `:ro` mount that blocked automake's test driver, a
`DESTDIR` mount of the host prefix, and an absolute `TESTS=` override that
matches no automake rule — were all invisible to the suite and all found by
running the thing.

## D19 — the standard tests its own assets by running them, and only its assets

**What is tested:** the shipped assets, executed against a real container on a
real runner.

**What is not tested:** the documented contract. `conventions.md` and
`teaching-the-standard.md` are prompts for Claude, and this project's mission is
that repo-infra carries the standard while **Claude does the conversion**. A
conversion leans on judgement about a varied target. A fixture asserting "the
document says enough" would only ever prove it says enough for that one shape —
a false green with machinery attached. Doc-driven fixture generation was
considered and rejected for exactly this reason.

The consequence is honest and worth stating: **a gap in the written contract
will not be caught by CI.** It is caught by a human converting a repository, and
the remedy is the teach path, not a test.

## The self-test arrives through the standard's own front door

A new detected ecosystem, `repo-infra`:

```json
{
  "id": "repo-infra",
  "signals": { "all": ["skills/repo-infra/assets/manifest.json"] },
  "ci_block": "ci-repo-infra-selftest"
}
```

It carries no `version_files`. That is an established shape — `go`,
`checkmk-plugin` and `perl-mkpl` have none — and correct here: repo-infra's
version comes from its `claude-plugin` and `python` ecosystems.

**Why an ecosystem rather than a special case.** Three properties fall out of it,
and no other route has all three:

1. **Required from day one, with no ruleset change.** `ci-passed` is the single
   required context (D2) and its `needs:` list is generated by the assembler from
   the blocks that went into `ci.yml`. A job inside `ci.yml` is therefore
   required automatically. The alternative — a separate workflow — needs a third
   required context, and `REQUIRED_CONTEXTS` is hardcoded to
   `{"ci-passed", "changelog-updated"}` in `apply.py` and `state.py` and shipped
   to every repository in `gh/ruleset-main.json`. Adding a third there would
   require a check that no other repository has.
2. **No exemption from its own standard.** repo-infra's self-test is installed by
   the same detection mechanism as every other block, and its `.github/` stays
   exactly the assembler's output.
3. **The signal is a true property, not a name.** "This repository ships
   repo-infra's assets" is a real, file-detectable fact. By the settled four-repo
   split exactly one repository has it, and any repository that vendored those
   assets would want this block too.

`test_this_repository_is_what_the_assembler_would_install` currently asserts
`result.ecosystems == ["claude-plugin", "python"]`. It becomes a three-element
list. **That test failing is the proof the wiring is real**, not an obstacle to
route around.

## The block — `assets/ci/ci-repo-infra-selftest.yml`

```yaml
  repo-infra-selftest:
    name: Container self-test
    runs-on: ubuntu-latest
    timeout-minutes: 20
    steps:
      - uses: actions/checkout@v7
      - name: Install the autotools host toolchain
        run: |
          sudo apt-get update
          sudo apt-get install -y autoconf automake gettext podman
      - run: python3 -m pytest -m container -v tests
```

The `apt-get` line is deliberately **the same fixed toolchain string
`ci-perl-autotools` installs**. Podman on an Ubuntu runner is the untested link;
this exercises the exact line that carries it.

A test asserts the two blocks install byte-identical toolchains. Without it the
self-test could keep passing against a toolchain the autotools block no longer
ships, which is the one way this block could go green while being worthless.

## The test — marked, so the fast gate stays fast

One implementation, two callers:

```
python3 -m pytest -q tests        # unchanged, sub-second, no podman needed
python3 -m pytest -m container    # opt in locally when touching the assets
```

`pytest.ini` registers a `container` marker and deselects it by default. A
developer without podman is unaffected; a developer changing `container.mk` runs
the same thing CI runs, rather than one that only reproduces by pushing.

## The fixture — one shape, chosen to be the strict one

`tests/fixtures/autotools-driver/`: `configure.ac`, `Makefile.am`, `t/*.t`,
`Containerfile`.

**Deliberately no `TEST_EXTENSIONS`.** Automake then emits literal per-test rules
(`t/basic.t.log: t/basic.t`) instead of a permissive `.t.log:` suffix rule. That
is the shape that exposed D18's absolute-`TESTS=` bug: with a suffix rule both
the absolute and relative forms match, and the bug hides. A fixture that passes
the strict shape passes the permissive one, so one image build covers both.

**The fixture is a fixture, not an asset.** No version marker, absent from
`manifest.json`, not drift-checked. `test_every_non_yaml_asset_is_covered_by_a_test`
walks `assets/`, so a fixture under `tests/` does not disturb it.

**The `Containerfile` pins its base image by digest.** A floating tag makes this
required check fail for upstream reasons; a digest is reproducible and bumping it
is a visible, reviewable change.

## What it asserts — one image build, many assertions

The image build is the expensive step, so it happens once and the assertions
share it.

| Property | Why only execution catches it |
|---|---|
| `autoreconf` emits zero warnings | proves the `if !CONTAINER_DRIVER` guard from D18's contract |
| native mode runs the real suite; `container` and `test-dev` do not exist | proves the conditional actually gates, rather than the file merely containing `if` |
| driver mode `make test` passes | proves the image builds and the `make test` seam reaches inside it |
| `make dist` leaves a tarball **on the host** | the release path; the tarball must come out of the image |
| `test-dev TARGET=…` runs the **live** host copy | proven by making the host copy `exit 1` and requiring failure. Silently broken twice in one branch |
| `test-dev` with no `TARGET`, `install` with no `DESTDIR` | a string assertion cannot prove `make` aborts |

**Prove liveness by exit status, never by TAP text.** Automake's default driver
judges a test by its exit status, so a script printing `not ok 1` while exiting 0
reports PASS. A liveness check written that way proves nothing and looks like it
works.

## Cost, and the risk accepted deliberately

Roughly 3–5 minutes per pull request: one `apt-get`, one image build, one suite.

The self-test is **required from day one**. A container-registry outage therefore
blocks merges, with an admin override as the escape hatch. This was chosen
knowingly over an advisory check: an advisory check that goes red and stays red
teaches everyone to ignore it, and the assets are this project's product.

## Deliberately not now

- **Testing the documented contract.** See D19. This is a decision, not a
  deferral.
- **A second fixture shape.** The strict shape subsumes the permissive one for
  every property listed above. A second shape is a teach when a real defect
  escapes the first.
- **Fixtures for other ecosystems.** The container driver is autotools-shaped;
  nothing else has crossed the D16 threshold yet.
- **Reconciling the duplicated toolchain string** between `ci-perl-autotools`
  and this block into a shared fragment. Two literal copies of four package names
  are cheaper than a mechanism. A test pinning the two strings equal ships with
  this work instead — see the assertion named above — so they cannot drift
  silently, which is the only thing a shared fragment would have bought.

## Open questions

None outstanding. Four were resolved on 2026-08-24 and are folded in above:
whether to test the docs (no — D19), where the test lives (a marked pytest test
with its own CI job), how it becomes required (a detected ecosystem, so
`ci-passed` picks it up), and how many fixture shapes (one, the strict one).
